# 小天 AI 助手教师端 — 当前版本说明

> 版本: v1.0.0 | 日期: 2026-06-01
> 状态: 交互原型（mock），适合内部演示与评审
> 构建: npm run build 通过，TypeScript 0 错误

---

## 1. 当前版本定位

当前版本是**"小天 AI 助手教师端交互原型"**。

目标不是展示最终视觉，不是展示真实数据，而是验证：

1. 教师端 AI 搜索是否能承接老师自然语言需求
2. AI 洞察是否能从学情问题出发给出教学建议
3. 推荐动作是否能进入后续教学流程
4. 生成内容是否支持预览、编辑、加入练习篮、布置确认
5. 首页快捷操作、AI 搜索页快捷操作、洞察动作是否统一

## 2. 当前已完成能力

### 2.1 首页

- 教师端首页结构（布置练习、课堂教学、更多课本、小天 AI、AI 洞察、练习报告）
- 小天 AI 入口（点击跳转 `/ai-search`）
- 首页输入框（Enter 跳转 `autoRun`，空输入不跳转）
- 首页快捷操作 4 个（生成听写 / 查同步资源 / 智能组卷 / 快速制卡）
- AI 洞察卡片展示（最多 3 条，按优先级排序）
- 练习报告区域

### 2.2 AI 搜索页 (`/ai-search`)

- 自然语言搜索（支持 11 种 intent 路由）
- 近期搜索记录展示
- "大家都在搜"趋势展示
- "试试"标签快速搜索
- 搜索自动执行（`autoRun=1`）
- `query` / `source` URL 参数支持
- 搜索结果统一渲染（AISearchResultRenderer）
- 搜索 loading 态 + 空态

### 2.3 AI 洞察（Insight V1）

- 首页最多展示 3 条洞察
- **错词洞察**: 课标词错误率 ≥ 30% 触发
- **听力/听说洞察**: 得分率 < 60% 或相对下降 ≥ 10% 触发
- **写作洞察**: 作文批改数据驱动
- **考前 30 天提醒**: 自动计算距考试天数，首页置顶
- **样本量不足轻提示**: 样本 ≤30% 时降级为低风险，只展示轻提示
- **查看分析 Drawer**: 打开右侧 66vw Drawer，展示完整洞察详情
- 洞察详情包含: 问题概述 → 数据依据 → 教研判断 → 教学建议 → 推荐动作 → 处理按钮
- 资料按钮: 忽略 / 稍后提醒 / 标记为已处理
- 文案安全检查: 不出现技术词（AI、workflow、agent 等）

### 2.4 洞察推荐动作

13/14 个动作已接入 mock 闭环：

**generate_content (6 个)**:
- 布置错词强化 (`assign_wrong_word_practice`)
- 生成作文讲评 (`writing_review`)
- 推荐范文 (`recommend_model_essay`)
- 布置二次修改 (`writing_revision`)
- 推荐模拟卷 (`exam_mock`)
- 生成专项训练 (`generate_special_practice`)

**navigate 跳转 (5 个)**:
- 生成词汇听写 (`vocab_dictation`)
- 错词重练 (`wrong_word_repractice`)
- 推荐听力专项 (`listening_special`)
- 推荐听说模拟 (`recommend_speaking_mock`)
- 推荐冲刺训练 (`exam_sprint`)

**view 面板 (1 个)**:
- 查看错词学生 (`view_wrong_word_students`)

**mock 占位 (1 个)**:
- 提醒未完成学生 (`remind_unfinished`)

### 2.5 推送内容处理闭环

- **GeneratedContentPanel**: 按内容类型展示（词表/题型/讲评要点/范文/模拟卷）
- **GeneratedContentEditPanel**: 编辑内容（删词/调难度/改名称/勾选要点）
- **练习篮接入**: 去重（重复提示）、成功提示、不进入布置
- **布置确认**: 进入 AssignmentConfirmPanel，携带内容信息
- **布置成功/取消**: 成功 → 状态更新，取消 → 返回上一步

### 2.6 快捷操作统一

- 首页快捷操作、AI 搜索页快捷操作统一走 `quickActionController`
- 7 个 source 值注册到 `EntrySource` 类型
- `buildSearchUrl(query, source, autoRun)` 标准化 URL 构建
- 首页快捷操作点击后自动跳转并执行

## 5. 推荐演示路径

### 路径 1: 首页快捷操作（30 秒）
首页 → 点击"生成听写" → 自动进入 `/ai-search` → 自动执行 → 展示生成结果

> 验证: 老师主动发起任务，一键直达，不需要两次操作

### 路径 2: AI 搜索自然语言（30 秒）
首页输入框输入"来一篇阅读理解" → 按 Enter → 自动跳转 → 展示任务和资源结果

> 验证: 老师可以用自然语言布置任务

### 路径 3: AI 洞察查看分析（1 分钟）
首页 AI 洞察 → 点击"查看分析" → 右侧 Drawer 打开 → 查看数据依据、教研判断、推荐动作

> 验证: 老师看到洞察 → 理解为什么 → 知道该做什么

### 路径 4: 洞察推荐动作 → 生成内容 → 布置（2 分钟）
首页错词洞察 → 查看分析 → 点击"布置错词强化" → 生成错词强化内容 → 预览 → 编辑（删除一个词） → 保存 → 回到预览 → 加入练习篮 → 布置给学生 → 布置确认 → 取消/确认

> 验证: 从洞察到布置的完整链路

### 路径 5: 考前提醒（1 分钟）
切换考前 mock → 首页考前训练提醒置顶 → 点击查看分析 → 推荐模拟卷 → 预览模拟卷 → 布置确认

> 验证: 考前场景的特殊处理

## 6. 演示时需要说明的话术

> "这是当前小天 AI 助手的原型。现在还不是正式产品版本，洞察数据、资源列表、布置发布都是 mock 的，主要是跑通流程。
>
> 我们想验证的是：老师从首页看到问题 → 进入 AI 洞察看分析 → 看推荐动作 → 生成练习或推荐资源 → 老师确认后布置给学生，这个路径顺不顺。
>
> 目前数据是模拟的，比如这个 55% 的错误率、72% 的词汇得分率，真实接入后会根据班级实际练习数据动态生成。写作模型、听力地区规则后面也会接真的。
>
> 大家可以重点关注：流程是不是太长？按钮是不是清楚？文案是不是像教研老师在说话？哪些地方需要更像天学网？"

## 7. 已知限制

1. **样式不是最终版** — 视觉尚未对齐天学网教师端设计规范
2. **数据不是真实数据** — 所有洞察、学生、资源均为 mock
3. **洞察规则仍需教研确认** — 当前阈值（30% 错词、60% 得分率等）为假设值
4. **地区听说规则需补官方数据** — 仅广东已确认题型
5. **写作评分待接系统模型** — 当前使用 mock WritingModelOutput
6. **推荐动作部分仍是 mock** — "提醒未完成学生"等为占位提示
7. **推送内容编辑能力为基础版** — 不支持添加新词、批量编辑
8. **资源选择和真实资源库未对接** — 搜索结果来自 mock
9. **适合内部评审，不适合外部客户演示** — 数据真实性不足以支撑客户决策
10. **需结合真实教师端做 UI 对齐** — 当前页面结构与天学网存在差异
