# 异常场景与降级策略 v0.8

> **版本状态**：v0.8（Demo 阶段）
> **说明**：以下降级策略部分仅在前端 Dev 模式的测试场景中 mock 演示，正式产品需配合后端接口实现。

---

## 1. 异常场景总览

| # | 场景 | 触发条件 | 严重程度 | 是否阻断 |
|---|------|---------|---------|---------|
| S1 | 候选词不足 | 实际可用词 < 选择的 Top N | ⚠️ 警告 | 不阻断 |
| S2 | 可用题目不足 | 题库匹配题数 < 每日题量 | ⚠️ 警告 | 不阻断 |
| S3 | 回滚词不足 | Day N 回滚词 < ⌈题量/5⌉ | ⚠️ 警告 | 不阻断 |
| S4 | 有效作答率 < 50% | Day N-1 作答率低于阈值 | ⚠️ 警告 | 不阻断 |
| S5 | 稳定基线词不足 | < 3 个基线词 | ℹ️ 信息 | 不阻断 |
| S6 | 草稿篮过期 | 7 天未使用 | ℹ️ 信息 | 自动清除 |
| S7 | 草稿篮为空 | 无草稿词 | ❌ 阻断 | 阻断生成 |

> 所有异常提示均为轻提示（inline warning），不弹窗阻断发布。

## 2. 场景详情

### S1：候选词不足

```
触发：老师选择 Top 30，但实际只有 8 个可用高频错词
```

**页面表现**：
- 词表来源处显示："当前可用高频错词：8 个"
- 摘要不写 Top 30，写 "当前可用高频错词 8 个"
- 琥珀色警告条："当前可用高频错词仅 8 个，将基于现有词汇生成复习方案。"

### S2：可用题目不足

```
触发：每日题量 30 题，题库只匹配到 22 题
```

**页面表现**：
- 预览页显示实际题量："每日实际题量：22 题（目标 30 题）"
- 蓝色提示条："部分词缺少匹配题目，已从同一候选池补充有题词。"
- 琥珀色警告条："当前词表可用题目不足，已按可用题目生成 22 题。"

**降级逻辑**（正式需求时后端实现）：
1. 优先从同一候选池中找有题目的词
2. 如候选池耗尽，按实际可用题量生成
3. 不生成低质量或空题

### S3：回滚词不足

```
触发：每日题量 30 题，理论需要 6 道回滚题，Day 1 截止后实际只有 3 个符合条件的回滚词
```

**页面表现**：
- Day N 展示：27 道主复习题 + 3 道动态回滚题（而非 24+6）
- 琥珀色警告条："回滚词不足 6 道，已用主复习题补齐当天题量。"

**降级规则**：
- 不强行生成低质量回滚题
- 差额由主复习题补齐，保持题量不变
- 不回滚不完整的错误数据

### S4：有效作答率不足 50%

```
触发：Day 1 作答率仅 30%
```

**页面表现**：
- 有历史回滚池：
  > "上一复习日有效作答率不足 50%（30%），本次回滚题已结合上一次有效回滚池生成；不足部分由主复习题补齐。"
- 无历史回滚池：
  > "上一复习日有效作答率不足 50%（30%），暂不生成动态回滚题，已用主复习题补齐。"

**决策逻辑**：
```
if dayN_1AnswerRate < 0.5:
  if hasPreviousRollbackPool:
    → 合并上一次有效回滚池
    → 不足部分主复习补齐
  else:
    → 不生成回滚题
    → 全部主复习题
```

### S5：稳定基线词不足

```
触发：稳定基线词 < 3 个
```

**页面表现**：
- 不回显 "较首次练习提升 X%"
- 展示 "较首次练习提升：—"
- 蓝色提示条："稳定基线词数量不足（X 个），暂不计算整体提升。"
- 仍展示 "当前回滚题正确率：76%"

### S6：草稿篮过期

```
触发：items 中 expireAt < Date.now()
```

**处理**：
- 加载时过滤过期项（`loadVocabDraft` 中实现）
- 到期前 1 天 header 提醒："明天将自动清空"

### S7：草稿篮为空

```
触发：草稿篮 items 数量 = 0
```

**处理**：
- 显示空状态："草稿篮为空"
- 底部按钮 disabled + grayed out

## 3. 降级原则

| 原则 | 说明 |
|------|------|
| **不阻断发布** | 所有异常提示为 inline warning，不弹窗 block |
| **如实展示** | 数据不足就写着不足，不夸大、不编造 |
| **题量保持** | 回滚题不足时补齐总题量，不减少每日练习量 |
| **低样本不适用** | 作答率低时不使用不完整数据生成回滚题 |
| **老师可知** | 所有降级信息对老师透明可见 |

## 5. 已确认 / 待确认 / Demo 待补齐 / 评审点

### 已确认
- 所有异常不阻断发布
- 回滚词不足时主复习补齐
- 作答率 < 50% 的两种分支处理
- 基线词 < 3 个不计算提升
- 测试场景仅 Dev 模式可用

### 待确认
- 作答率 < 50% 时"上一次有效回滚池"的数据保留策略
- 候选词不足时是否自动降低 Top N 选择
- 题目不足时自动补齐的范围上限
- 正式产品中是否需要错误边界 + 全局 fallback 组件

### Demo 待补齐
- 异常场景在真实数据下的验证
- 后端异常（接口超时、500）的前端兜底

### 评审点
- 50% 作答率阈值是否需要按场景调整（如假期期间作答率自然低）
- 是否需要加入"老师手动关闭自动回滚"的选项（当前固定开启）
- 是否需要异常场景的埋点和数据上报
