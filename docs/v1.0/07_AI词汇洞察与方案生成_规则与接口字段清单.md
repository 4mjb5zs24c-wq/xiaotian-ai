# AI 词汇洞察与方案生成 — 规则与接口字段清单

> 版本：v1.1  
> 更新日期：2026-06-24  
> 用途：前后端开发对齐材料，覆盖所有页面模块的展示规则、取数规则、计算公式、空态/异常处理和接口字段。

## 全局约定

### 去重规则

**高频错词去重沿用平台现有词汇去重规则。具体以平台词汇中心 / 错词库 / 后端返回的词汇唯一标识为准。当前去重口径待确认。**

正式开发建议由后端返回已聚合后的高频错词列表，前端不自行做复杂去重。

后端返回字段建议包含：

- `wordId`：平台词汇唯一标识
- `wordText`：前台展示词汇
- `displayText`：展示用词汇名称，如有
- `errorCount`：错误次数
- `affectedStudentCount`：涉及学生数
- `scoreRate`：得分率
- `errorRate`：错误率
- `errorReasons`：错因分布
- `wrongPronunciations`：多个错音列表

前端只负责展示后端返回的聚合结果。

**Demo 说明**：Demo 中为避免重复展示，临时按 mock 数据中的 `wordId` 聚合（无 `wordId` 时 fallback 到 `text.trim()`）。此逻辑仅为 demo mock 去重逻辑，正式规则以平台现有去重规则和后端返回为准。不要把 demo 的去重逻辑写成正式产品规则。

### planId 全链路规则

1. 方案生成成功后，后端返回 `planId`。
2. 干预记录、练习报告列表、方案报告页都通过同一个 `planId` 关联。
3. `/vocab-plan-report/:planId` 根据 `planId` 查询完整方案报告。
4. 如果 `planId` 无效，不要跳转普通 `/practice-reports`，应展示"报告不存在或暂无数据"。

### 未确认项汇总

| 项目 | 内容 |
|------|------|
| 去重口径 | 高频错词去重口径待确认：需确认平台现有错词/词汇去重规则，包括是否按 wordId、标准词、展示词、大小写、词形变化、短语别名等进行合并。 |
| 数据少阈值 | 数据少阈值暂待确认：高频错词数 < 20？或有效作答人数不足 N？ |
| 词汇闯关 2 触发条件 | "首批作答数据"的触发条件待确认：达到一定作答人数后生成，或按固定时间点生成。 |
| 初三/高三教材切换 | 初三/高三默认课标词复习，是否允许切换教材复习？（当前 UI 允许切换） |
| 薄弱学生阈值 | 薄弱/较好判定得分率阈值待后端确认 |
| 方案生成方式 | 方案生成是同步返回还是异步+轮询？是否需要 streaming？ |
| 词汇学习策略计算 | 词汇学习策略维度暂标记「待完善」，后续需定义具体计算规则 |

## 模块 4：高频错词列表

| 项目 | 内容 |
|------|------|
| **页面/模块** | 词汇能力洞察页 — 高频错词工作台（左栏列表） |
| **入口** | 页面中部，双栏布局左侧 |
| **前端展示规则** | 按词聚合后的高频错词列表。每行展示：词文本 + 主错因标签 + 严重程度标签 + 得分率 + 受影响学生数 + 错误次数。顶部有错因筛选标签（不会写/读不准/生词/不会用）。 |
| **取数/接口字段** | `WeakWordItem`（含 `wordId` / `wordText` / `displayText` / `scoreRate` / `errorRate` / `errorCount` / `affectedStudentCount` / `mainErrorType` / `severity` / `totalActualScore` / `totalFullScore` / `evidences[]` / `wrongForms[]` / `issueTypes[]`） |
| **计算规则** | **去重**：沿用平台现有词汇去重规则，后端返回已聚合数据。**得分率** = `totalActualScore ÷ totalFullScore × 100`（聚合后计算）。**错误率** = `100 - 得分率`。多空题按空算小题。 |
| **排序/筛选** | **排序（先聚合、再排序、再取 Top N）**：1) 错误率从高到低 2) 涉及学生数从多到少 3) 错误次数从多到少 4) 有效作答次数从多到少。**数量口径**：词汇洞察数据池取 Top 50，列表默认展示 Top 12。**不足时按实际数量展示，不硬凑重复词**。 |
| **空态/异常** | 无高频错词时展示「暂无高频错词数据」；无 `totalActualScore`/`totalFullScore` 时沿用后端返回的 `scoreRate`（兼容旧数据） |
| **当前 mock** | `ENRICHED_MOCK_WEAK_WORDS`（含 wordId 优先 + text.trim() fallback 去重 + totalActualScore/totalFullScore 聚合），经 `deduplicateWeakWords` + 排序 + filter |
| **后端支持** | **是 — 核心接口**。后端需返回已聚合的高频错词列表，包含 totalActualScore / totalFullScore。前端只负责展示和排序。 |
| **待确认** | 去重口径（见全局未确认项） |

## 模块 8：生成词汇提升方案弹窗（VocabInsightPlanModal）

| 项目 | 内容 |
|------|------|
| **页面/模块** | 词汇洞察页 → 词汇提升方案弹窗 |
| **入口** | 顶部概览区「生成词汇提升方案」按钮 |
| **前端展示规则** | **不出现一周/两日方案类型选择**。**不出现年级/教材/单元选择**。默认生成词汇闯关 1 + 词汇闯关 2（共 2 份练习）。每份练习 50 题。每份尽量覆盖 50 个词。**不向老师展示回滚、补题等后台规则**。展示信息：覆盖高频错词 N 个 / 班级 / 有效期 / 共 2 份练习 · 每份 50 题。底部：重新生成 + 确认布置。弹窗视觉居中。 |
| **取数/接口字段** | **请求**：`timeRange`、`classId`、`weakWordIds[]`（当前筛选范围 Top 50 高频错词）、`weakStudentIds[]`。**响应**：`planId`、`exercises[]`（每份含 `name`、`publishTime`、`deadline`、`questionCount`、`wordCoverage`） |
| **计算规则** | **后端生成规则**：1) 词汇闯关 1：基于当前筛选范围 Top 50 高频错词生成；2) 词汇闯关 2：基于词汇闯关 1 的作答数据进行巩固生成；3) 词汇不足 50 个时，一个词可对应多道题；4) 题型不足时，优先用本难度其他题型补充；5) 同难度不足时，从低难度补充；6) 回滚、补题、一个词多题等规则不展示给老师，只作为后端生成规则。 |
| **排序/筛选** | 无 |
| **空态/异常** | **无数据（高频错词数 = 0 或有效作答记录 = 0）**：不允许生成方案，展示「当前范围内暂无可用于生成方案的数据，请切换时间范围或复习范围后重试。」**数据少（高频错词数 < 20 或有效作答人数不足，阈值待确认）**：允许生成，但展示提示「当前范围内可参考数据较少，生成结果可能不够充分，建议结合实际教学情况使用。」接口异常时展示错误提示并允许重试。 |
| **当前 mock** | `weakWordCount` 和 `weakStudentCount` 由页面传入，方案内容纯静态 mock，Loading 为前端 `setInterval` 动画 |
| **后端支持** | **是 — 核心接口**。需后端实现方案生成 + 回滚 + 补题逻辑，前端只展示结果。 |
| **待确认** | 词汇闯关 2 的"首批作答数据"触发条件（达一定作答人数？固定时间点？）；数据少阈值 |

## 附录 B：完整排序规则（高频错词）

```
先按词聚合 → 再排序 → 再取 Top N

排序优先级（从高到低）：
1. 错误率从高到低
2. 涉及学生数从多到少
3. 错误次数从多到少
4. 有效作答次数从多到少

得分率 = totalActualScore ÷ totalFullScore × 100
错误率 = 100 - 得分率
```
